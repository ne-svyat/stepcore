# StepCore — тестирование на реальном устройстве

StepCore сейчас нужнее **разные телефоны и реальные сценарии**, чем ещё сто
синтетических прогонов.

Этот файл нужен, чтобы отчёт можно было разобрать, а не гадать по фразе
«шагомер иногда врёт».

---

## 1. Что тестировать в первую очередь

| Приоритет | Сценарий | Зачем |
|---|---|---|
| 🔴 высокий | фон с заблокированным экраном | OEM по-разному душат sensor delivery и foreground services |
| 🔴 высокий | `WALK → RUN → WALK` | текущая ветка v442 впервые соединяет background Motion Truth с `runSteps` |
| 🟠 высокий | обычный день vs системный шагомер | ловит крупные потери/пересчёт, но системный шагомер не считать абсолютной истиной |
| 🟠 средний | долгий сон / выгрузка приложения | важны delayed batches и восстановление состояния |
| 🟡 средний | батарея за несколько часов/сутки | нужен device corpus, а не одно число с Xiaomi |
| 🟡 средний | SYNX / автокалибровка | BETA: особенно полезны неправильные режимы, странные вопросы и stale data |
| 🟢 UX | Экспедиция / Vault | BETA: ломанные переходы, потеря состояния, непонятные действия |

## 2. Быстрый smoke-test

Не надо считать каждый шаг вручную.

1. Запусти StepCore.
2. Заблокируй экран.
3. Пройди обычные 5–10 минут.
4. Разблокируй.
5. Проверь, что счёт вырос и сервис не умер.
6. Если есть системный шагомер, запиши **оба значения** как две независимые оценки.

Большое расхождение интересно. Разница в несколько шагов сама по себе ничего
не доказывает.

---

## 3. Текущий приоритетный тест v442 — WALK → RUN → WALK

**Цель:** проверить background RUN/WALK без ручного подсчёта шагов.

**Подготовка:**
- экран StepCore-телефона заблокирован;
- телефон всё время в одном реальном положении: карман / рука / рюкзак;
- таймер лучше поставить на другом телефоне;
- `Energy Gate: тень` выключена;
- `Сбор при выключенном экране` не включать специально, если разработчик не попросил.

**Таймлайн:**
- `00:00–01:00` обычная ходьба;
- `01:00–04:00` обычный стабильный бег, не спринт;
- `04:00–05:30` обычная ходьба;
- `05:30–06:00` спокойно стоять;
- после `06:00` разблокировать StepCore.

**Полезный результат:**
- во время бегового участка появляется background RUN;
- `runSteps` реально растут;
- появляется чистый RUN corpus для автокалибровки;
- после бега режим возвращается в WALK;
- настоящие шаги не исчезают массово на переходах.

## 4. Полевой сбор

На главном экране:

**Инструменты → Полевой сбор одним тумблером**

Он включает вместе:
- журнал решений;
- признаки походки;
- сырьё вокруг события.

Это диагностические журналы. Они не должны менять количество шагов.

Отдельные переключатели:
- **Сбор при выключенном экране** — более тяжёлый background motion-сбор;
- **Energy Gate: тень** — отдельный low-power диагностический режим.

Не включай всё подряд «на всякий случай». Чем больше приборов одновременно,
тем труднее понять, какой именно режим воспроизводился.

## 5. Что приложить к отчёту

Минимум:
- модель телефона;
- Android + оболочка;
- версия StepCore;
- где лежал телефон;
- был ли экран заблокирован;
- что именно делал человек и примерно когда;
- что ожидалось;
- что произошло.

Если использовал диагностику, приложи только релевантный фрагмент журнала /
экспорт / скриншот.

## 6. Как отправить

**Обычный баг:**
[Bug report](https://github.com/ne-svyat/stepcore/issues/new?template=bug.yml)

**Структурированный полевой тест:**
[Field report](https://github.com/ne-svyat/stepcore/issues/new?template=field-test.yml)

Не нужно писать вывод за StepCore. Фраза «с 14:32 до 14:36 бежал, телефон был
в правом кармане, приложение оставило WALK» полезнее, чем «алгоритм бега
сломался».
