## Как устроен проект

```text
TYPE_STEP_COUNTER
      │
      ▼
[A] QUANTITY INTEGRITY
    Hybrid Guard
    Temporal Ledger
      │
      ▼
[B] MOTION TRUTH             ← v442, текущая полевая проверка
    WALK / RUN / UNKNOWN
      │
      ├──────────────► история / статистика
      │
      ▼
[C] AUTO CALIBRATION         ← корпус уже собирается, профиль ещё не строится сам
      │
      ▼
[D] SYNX                     ← обучение и очистка персонального корпуса
      │
      ▼
[E] L4                       ← персональная модель + drift, дальше по плану
```

Экспедиция и Vault живут рядом с этой цепочкой и не должны диктовать ядру,
как считать шаги.

## Что уже реально есть

### Аппаратный счёт шагов

StepCore не пытается изобрести количество шагов из акселерометра. Источник
количества — аппаратный `TYPE_STEP_COUNTER`.

Сырые motion-сенсоры используются как **доказательства контекста**:
они помогают разбирать тряску, движение и переходы, но не создают количество
из воздуха.

Текущий background guard умеет:
- удерживать подозрительные дельты до физической проверки;
- не путать включение lockscreen с настоящей разблокировкой;
- защищать большие delayed batches на границе `ходьба → тряска`;
- отбрасывать только ту часть, для которой есть post-event provenance;
- возвращаться из SHAKE в GAIT без обязательной разблокировки.

Это не означает, что все телефоны Android уже поверены. Полевой корпус пока
сильно смещён в сторону Xiaomi 13T Pro / HyperOS.

### История, профиль и диагностика

Есть дневная история, аналитика, Timeline, профиль, ручные калибровки и
инструменты диагностики.

В разделе **Инструменты** есть «Полевой сбор одним тумблером». Он включает
только журналы решений, признаков походки и сырья вокруг события. Эти журналы
наблюдают систему и не должны сами менять счёт шагов.

## Офлайн: точная формулировка

В [`AndroidManifest.xml`](app/src/main/AndroidManifest.xml) **нет**
`android.permission.INTERNET`.

Это означает: **сам StepCore не имеет разрешения Android на сетевое
соединение**. Нет аккаунта StepCore, рекламного SDK, облачной синхронизации
или встроенной аналитики.

В текущей ветке для semantic-контекста WALK/RUN используется Google Play
services Activity Recognition. Google Play services — отдельный системный
компонент со своими разрешениями, поэтому здесь нет ложного обещания
«вообще ни один компонент телефона никогда не обращается к сети».

Количество шагов и локальная база StepCore от интернета не зависят.

### Разрешения StepCore

| Разрешение | Зачем |
|---|---|
| `ACTIVITY_RECOGNITION` | аппаратные step-сенсоры и Activity Recognition |
| `HIGH_SAMPLING_RATE_SENSORS` | короткие физические пробы accel/gyro/rotation |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_HEALTH` | непрерывный счёт как foreground health-service |
| `WAKE_LOCK` | короткие контролируемые окна работы там, где это нужно |
| `POST_NOTIFICATIONS` | уведомление работающего счётчика |
| `VIBRATE` | тактильные сигналы и калибровка |
| `ACCESS_FINE_LOCATION` | только явная GPS-калибровка длины шага |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | защита длительной фоновой работы от OEM battery killer |

## Vault (BETA)

Vault намеренно не торчит отдельной кнопкой на главном экране.

**Как войти:**

1. На главном экране сделай **двойной тап по луне**.
2. В течение **5 секунд** сделай **двойной тап по свитку**.
3. После принятой первой части будет короткая вибрация.

Внутри — локальные зашифрованные заметки. Криптографическое ядро использует
scrypt и AES-256-GCM; Vault работает в отдельном Android-процессе `:vault` и
не остаётся отдельной карточкой в списке недавних приложений.

> [!CAUTION]
> Vault всё ещё BETA. Он уже пригоден для нормального использования, но проект
> не заявляет независимый security-аудит. Не храни единственную копию важных
> данных без экспорта и материалов восстановления.

## Экспедиция (BETA)

Экспедиция — отдельный экспериментальный режим, где реальные шаги становятся
ресурсом мира: сезон, дни, события, окружение, журнал, архив и радар.

Важная деталь: мир **не крутит тяжёлую симуляцию в фоне**. При открытии режима
он догоняет прошедшее по накопленным данным. Это экономит батарею и честнее,
чем делать вид, что отдельный игровой процесс жил всё это время.

Режим уже можно запускать и исследовать. **Готовой игрой он пока не считается.**

## SYNX и автокалибровка (BETA)

SYNX — не магическая кнопка «AI понял походку». Сейчас это исследовательский
контур персонализации:

- собирает корпус движения;
- строит и хранит сессии;
- умеет спрашивать пользователя о режиме и уклоне;
- содержит агент уклона и проверки его зрелости;
- принимает canonical WALK/RUN из новой Motion Truth цепочки;
- готовит данные для будущей персональной модели.

**Чего пока нет:** полностью автоматического, доказанно устойчивого цикла
`наблюдение → персональный профиль → SYNX → L4` без ручной калибровки.

Автокалибровка движется именно туда: обычная ходьба и обычные пробежки должны
со временем заменять отдельные лабораторные ритуалы. В v442 начат сбор чистого
tempo corpus, но автоматическое продвижение корпуса в профиль ещё впереди.

## Установка

Готового релиза в Google Play пока нет.

Сборки лежат в GitHub Actions:

**Actions → последняя успешная `Build APK` → artifact `stepcore-apk`**

Требуется **Android 11 (API 30) или новее**.

На MIUI/HyperOS фоновые ограничения особенно важны:
[MIUI_SETUP.md](MIUI_SETUP.md).

> [!NOTE]
> Артефакты из `main` — development builds. Перед обновлением важных локальных
> данных разумно иметь резервную копию.

## Нужны тестировщики

StepCore разрабатывается в основном на одном устройстве. Поэтому Samsung,
Pixel, Nothing, OnePlus, Oppo, Huawei и другие OEM полезнее любого ещё одного
эмулятора.

**Сейчас особенно ценны:**
- фоновый счёт при заблокированном экране;
- большие расхождения с системным шагомером за обычный день;
- переходы `ходьба → бег → ходьба`;
- поведение после долгого сна CPU / убийства процесса;
- расход батареи;
- странности SYNX, Экспедиции и Vault;
- всё, где интерфейс обещает одно, а система делает другое.

### Как тестировать

Полная короткая инструкция:
**[docs/TESTING.md](docs/TESTING.md)**

Для обычного бага:
**[создать bug report](../../issues/new?template=bug.yml)**

Для структурированного полевого теста:
**[отправить field report](../../issues/new?template=field-test.yml)**

GitHub Issues публичны. StepCore ничего не отправляет туда автоматически:
файл, текст или скриншот прикладывает сам тестировщик.

## Что НЕ стоит ожидать прямо сейчас

- медицинской или сертифицированной fitness-точности;
- гарантированно правильного RUN/WALK на любом Android;
- готовой автоматической персональной калибровки;

Если одно из этого изменится, этот список должен стать короче. Не наоборот.

## Разработка

Проект развивается измерениями, а не количеством придуманных порогов.

Основные правила:
- quantity и классификация — разные ответственности;
- новая гипотеза не получает production authority без измерения;
- правило не отвечает за границей своей поверки;
- после двух неудачных попыток меняется метод исследования, а не третья цифра порога;
- unit tests проверяют state machines, а реальное поведение сенсоров проверяется на устройстве;
- CI запускает unit tests до сборки APK.

Критические state machines сейчас имеют отдельные тесты
`HybridGuardTest` и `HybridMotionTest`.

Разработка ведётся с телефона через **Termux + GitHub**.
